# Notion 사용성 고도화

2026-11-04 기준. Nopetion의 기존 개인 모드와 서버 저장 구조를 유지하면서 진행한 개선 기록입니다. Notion의 전체 제품·협업·AI 기능과 동등하다는 의미는 아닙니다.

## 비교 기준

- [Notion 사이드바](https://www.notion.com/help/navigate-with-the-sidebar): 검색, 즐겨찾기, 중첩 페이지, 섹션 접기, 사이드바 너비 조절.
- [Notion 데이터베이스 뷰·필터·정렬](https://www.notion.com/help/views-filters-and-sorts): 같은 데이터를 여러 뷰로 탐색하고 뷰마다 독립적인 설정 유지.
- 최신 Notion은 홈을 사이드바 탭으로 통합하는 구조도 안내합니다. 이번 변경의 카드형 홈은 Nopetion의 기존 `/home` 경로를 확장한 것이며 최신 Notion의 모든 화면을 픽셀 단위로 복제한 것은 아닙니다.

## 구현한 개선

| 영역 | 동작 |
| --- | --- |
| 개인 홈 | 실제 최근 수정 문서와 즐겨찾기 조회 결과를 카드/목록으로 표시. 페이지 이동, 더 보기, 검색, 템플릿, 로딩·빈 결과·재시도 지원. |
| 사이드바 | 현재 경로 선택 표시, 즐겨찾기와 개인 페이지 섹션 접기 상태 저장, 운영체제에 맞는 검색 단축키 안내. |
| 사이드바 너비 | 개인 모드 홈과 문서에서 220–600px 드래그 조절 및 브라우저 저장. 핸들에 포커스 후 좌우 화살표로 10px, Shift와 함께 50px 조절. Home/End로 최소/최대, 더블클릭으로 기본 폭 복원. 모바일은 기존 오버레이 너비 유지. |
| 데이터베이스 | 뷰 종류별 상태 필터와 정렬을 문서 노드에 저장. HTML 내보내기/가져오기 왕복 보존. 기존 문서는 기본 설정으로 호환. |
| 읽기 전용 데이터베이스 | 뷰·필터·정렬 탐색은 허용하되 문서를 수정하거나 설정을 저장하지 않음. |
| 블록 명령 | 반복 생성한 데이터베이스와 AI 노트에 고유 식별자를 부여. 문서 경계·편집 권한에 맞춰 이동/복제 메뉴 비활성화. |

## 범위와 남은 차이

- 기존 전역 검색, 페이지 멘션, 백링크, 동기화 블록, 템플릿, 문서 이력, 휴지통, 오프라인 기능은 별도의 구현이 이미 있습니다. 이번 개선으로 새로 만든 기능으로 집계하지 않습니다.
- 뷰 설정은 현재 지원하는 **뷰 종류별** 필터/정렬입니다. 같은 종류의 뷰를 여러 개 이름 붙여 생성하는 Notion의 임의 뷰 탭과는 다릅니다. 복합 필터·그룹·속성 노출까지의 동등성도 별도 과제입니다.
- 최근 문서 카드는 **최근 수정 시간**을 기준으로 합니다. 최근 열람 기록과 구분합니다.
- 사이드바 너비와 접기 설정은 현재 브라우저에 저장되며 계정의 다른 기기까지 동기화하지 않습니다.
- README에 정의된 개인 모드는 단일 소유자용입니다. 팀 초대, 공개 공유, Notion의 세부 권한·외부 자동화·AI 서비스 동등성은 이번 변경에 포함되지 않습니다.
- 로컬 PostgreSQL·Redis와 실제 서버를 실행했고 Tailscale HTTPS 상태 점검을 통과했습니다. 계정 생성·사용자 AI 로그인은 임의로 수행하지 않았으므로 실제 인증 세션에서 AI 제공자를 호출하는 전체 흐름은 아직 검증하지 않았습니다. 브라우저 UI 검증은 실제 컴포넌트와 모의 API를 사용하는 fixture이며 실제 사용자 데이터가 아닙니다.

## 재검증

```sh
pnpm --filter @docmost/editor-ext build
pnpm --filter client test
pnpm --filter client build
pnpm test:personal
```

실제 서버 검증은 README의 개발 환경을 준비한 뒤 수행합니다. 개인 홈에서 문서를 열고, 섹션과 너비 변경을 새로고침 후 확인합니다. 데이터베이스 표/보드에 서로 다른 필터와 정렬을 지정한 후 다른 페이지를 방문하고 돌아와 설정이 유지되는지 확인합니다. 읽기 전용 상태에서는 같은 조작으로 문서 저장 요청이 발생하지 않아야 합니다.

### 앞선 홈·사이드바 개선 검증 기록

- 클라이언트 테스트: 64개 파일, 691개 테스트 통과.
- 개인 모드 정책 테스트: 58개 통과.
- 편집기 확장 빌드, 클라이언트 TypeScript 검사 및 프로덕션 빌드 통과.
- 클라이언트 ESLint: 오류 0개, 기존 Fast Refresh 경고 7개. 빌드에는 기존 chunk 크기 및 deprecated `advancedChunks` 경고가 남아 있습니다.
- 브라우저: 실제 화면 컴포넌트 + 모의 API 데이터로 1440×900 라이트/다크, 390×844 모바일을 확인했습니다. 가로 넘침 없이 반응형 카드/모바일 사이드바가 표시되며, 섹션 접기 저장과 240→290px 키보드 너비 조절을 확인했습니다.
- 브라우저 fixture의 간접 앱 부트스트랩으로 중복 `createRoot` 경고가 발생했습니다. 이 경고가 없는 실제 로그인 세션의 전체 동작은 서버 환경에서 별도 확인해야 합니다.


## 문서 UI와 AI 후속 개선 (2026-11-04)

- 문서 본문 폭·제목·커버·아이콘·블록 간격, 탐색 헤더, 사이드바, 슬래시 메뉴와 데이터베이스 툴바를 정리했습니다. 글꼴·작은 글자·전체 너비는 실제 사용자 설정에 저장합니다.
- 제목으로 생성되는 오른쪽 목차는 자동 표시되고 hover/focus로 펼쳐지며 항목 클릭으로 해당 제목으로 이동합니다. 모바일에서는 메뉴의 목차를 사용합니다.
- 선택 메뉴·슬래시 Ask AI를 개인 AI 패널에 연결했습니다. 기본값은 요청 → 안전한 블록 미리보기 → 삽입/선택 교체입니다. 다시 생성·복사·버리기와 명시적인 백그라운드 직접 작성 모드를 지원합니다.
- 선택 편집은 요약·다듬기·번역과 맞춤법·간결하게·길게 프리셋, 추가 지시를 지원합니다.
- AI 참조 데이터에는 현재 페이지 제목·본문·선택 영역, 문서 안에 저장된 데이터베이스의 표시값 등이 포함됩니다. 권한이 확인된 서버 원문만 사용하고 다른 문서·첨부·외부 링크는 조회하지 않습니다. 본문 참조는 20,000자로 제한하며 생략 여부를 모델에 전달합니다. 선택한 원문은 별도 보존합니다.
- 저장 JSON과 에디터 JSON의 기본 속성 차이를 의미 비교로 처리한 뒤 서버 원문 해시로 검증합니다. 원문/제목 변경, 페이지 이동, 편집기 재생성, 읽기 전용, 중복 적용을 방어합니다.
- 완료된 AI 스트림 뒤의 연결 종료 오류와 cleanup 오류가 정상 결과나 원래 오류를 덮지 않도록 보완했습니다.

동작 비교 근거: [Notion AI 문서 편집](https://www.notion.com/help/guides/notion-ai-for-docs), [Notion AI FAQ](https://www.notion.com/help/notion-ai-faqs). 제품 동등성이나 모든 오류의 부재를 보증하는 것은 아닙니다.

### 추가 검토에서 남은 개선점

1. **미리보기 실행의 재접속 복원**: 추론은 성공했지만 응답이 유실된 경우 현재 다시 생성은 새 요청입니다. durable preview job/result receipt와 idempotency를 도입하면 중복 추론을 줄일 수 있습니다. 기본 모드는 승인 전 문서를 변경하지 않으므로 이 경우에도 중복 문서 삽입은 하지 않습니다.
2. **관련 프로젝트 문서 선택**: 현재 페이지의 맥락은 전달하지만, 다른 프로젝트 문서를 자동 수집하지 않습니다. 사용자가 참조 문서를 선택하고 권한·버전을 확인하는 별도 기능이 후속 과제입니다.
3. **긴 문서의 검색 기반 문맥 선택**: 현재는 앞/뒤 본문 발췌와 선택 원문을 사용합니다. 질문과 관련된 중간 문단을 검색하고 근거 위치를 표시하면 긴 문서의 답변 품질을 높일 수 있습니다.
4. **실제 계정 통합 검증**: 연결된 AI 계정/모델과 실제 저장·협업 세션에서 요청→미리보기→적용→새로고침을 확인해야 합니다. 테스트의 모의 응답은 실제 모델 답변 품질과 계정 사용 한도를 검증하지 않습니다.
